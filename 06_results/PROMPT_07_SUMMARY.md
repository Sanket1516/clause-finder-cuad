## 4. Test-run count (honest)
`06_results/test_runs/ledger.jsonl` has 4 lines: **2 are unit-test artifacts** (entries 1-2, synthetic fixture corpus, annotated in `ledger_notes.md`) and
**2 are real** (entry 3 baseline, entry 4 final) = one planned session, one evaluation per configuration. **Uncounted attempts:** before the real runs I made one attempt per configuration (baseline, final) that computed the test metrics in memory and then failed at the save step with `FileExistsError` (my output-file naming collided with the train artifacts). The old ledger logic wrote its entry only at save time, so these two attempts are **not in the ledger**. Their results were never printed, saved or looked at, and nothing was changed because of them; I then moved the ledger write to the start of `evaluate()` (so this cannot recur), changed the output file names, and ran the two real evaluations. So the honest count is: **2 recorded evaluations + 2 earlier aborted, unseen evaluations = 4 test-split evaluations started, none used for any decision**. The metric code was not touched by that fix.
The fresh-clone check re-ran both test evaluations in a throwaway clone (its own ledger) to confirm the saved metrics reproduce exactly; no decision used them.

## 5. Train/test gap (details in REPORT section 5)
Recall@4 is 0.448 on train and 0.448 on test (no gap; test 95% bootstrap interval [0.32, 0.57], n = 54). Correct abstention is 16/39 (0.41) on train and 3/10 (0.30) on test
(Wilson 95% [0.11, 0.60]); the train figure is optimistic because the gate was chosen on those same 39 queries. Test and train queries share contracts, so this is
generalisation to new questions, not new contracts. The small test sets (54 and 10) cannot detect small differences.
